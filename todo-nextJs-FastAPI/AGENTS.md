## AGENTS.md
이 문서는 프로젝트 내에서 자율적으로 코드를 수정, 테스트 및 실행하는 모든 AI 에이전트(AI Agents)의 역할, 작업 반경, 그리고 준수해야 할 프로토콜을 정의한다. 시스템 내의 모든 에이전트는 작업을 시작하기 전 반드시 이 지침을 숙지해야 한다.

## 1. 에이전트 역할 정의 (Agent Personas)
- 본 프로젝트는 효율적인 마이그레이션과 기능 신뢰성을 위해 AI 에이전트의 역할을 명확히 분리한다.

### 🌐 프론트엔드 엔지니어 에이전트 (Frontend Agent)
주요 임무: frontend/ 폴더 내 Next.js (App Router) 기반 UI 컴포넌트 구현 및 상태 관리 최적화.

- 행동 지침:
인터랙션이 발생하는 인풋창, 버튼 컴포넌트 수정 시 반드시 최상단에 'use client' 지시어가 누락되지 않았는지 검증할 것.
하드코딩된 스타일을 지양하고 Tailwind CSS 유틸리티 클래스를 조합하여 레이아웃을 구성할 것.

### ⚡ 백엔드 엔지니어 에이전트 (Backend Agent)
주요 임무: backend/ 폴더 내 FastAPI 기반 비즈니스 로직 및 RESTful API 설계.

- 행동 지침:
클라이언트의 모든 요청(Request) 및 응답(Response) 데이터는 schemas/ 폴더 안의 Pydantic 모델을 거쳐 유효성 검증(Validation)을 통과해야 함.
데이터베이스 작업은 SQLAlchemy ORM 규칙을 준수하며, 커밋 시점의 예외 처리(Try-Except)를 엄격히 적용할 것.

## 2. 작업 반경 및 환경 제약 (Environment & Constraints)
- 허용된 폴더 구조:
프론트엔드 작업은 오직 frontend/src/ 내부에서만 수행한다.
백엔드 작업은 오직 backend/app/ 내부에서만 수행한다.

- 패키지 관리 및 설치 제약:
임의로 외부 라이브러리를 설치하는 행동을 엄격히 금지한다.
추가 패키지가 반드시 필요한 경우 수정을 진행하기 전 인간 개발자(Owner)에게 명확한 사유와 함께 컨펌을 요청할 것.

## 3. 에이전트 실행 프로토콜 (Execution Workflow)
에이전트가 코드를 자율적으로 수정하고 실행할 때는 반드시 다음 3단계 프로세스를 차례대로 수행해야 한다.

- [Phase 1] 사전 분석 (Analysis)
코드를 수정하기 전, 해당 기능과 연동된 기능명세서(plan.md 혹은 requirements.md)의 [입력 조건] 및 [예외 처리] 조항을 먼저 파악한다.
- [Phase 2] 안전 수정 (Safe Implementation)
컴포넌트의 높이(h-)나 패딩(p-) 등 세로/가로 레이아웃을 조정할 때, 주변 요소가 압박받아 쪼그라들지 않도록 shrink-0 및 aspect-square 같은 방어적 클래스를 적절히 매칭한다.
테두리를 보이지 않게 처리할 때는 레이아웃 덜컥거림을 방지하기 위해 border-none 대신 border-transparent 속성을 우선 적용한다.
- [Phase 3] 실행 및 빌드 검증 (Execution & Verification)
코드 수정 완료 후, 터미널 명령어를 직접 실행하여 빌드 에러 및 문법 오류가 없는지 최종 검증한다.

`프론트엔드 검증 명령어: cd frontend && npm run build`

`백엔드 검증 명령어: cd backend && pytest (테스트 스크립트가 존재할 경우)`

## 4. 예외 및 실패 대응 지침 (Error Handling)
시스템 실행 도중 에러('...'이(가) 필요합니다. 또는 라우팅 꼬임 등) 발생 시, 코드를 맹목적으로 재생성하지 말고 여닫는 태그의 쌍(/>와 </button>) 및 파일 저장 상태를 재확인할 것.
마이그레이션 도중 프론트엔드와 백엔드 간 통신에서 CORS 차단 에러가 감지되면, 즉시 backend/app/main.py 파일의 CORSMiddleware 설정 상태를 디버깅할 것.
